# Authoritative Sources: Software Engineering and DevOps

## Purpose

Defines primary, authoritative documentation portals, language specifications, and package registries for software development, CI/CD, and DevOps tooling.

## Primary Source Registry

### Version Control & Control Planes
- **GitHub Documentation**: `https://docs.github.com/`
- **GitHub REST API Reference**: `https://docs.github.com/en/rest`
- **GitHub Actions Documentation**: `https://docs.github.com/en/actions`
- **GitHub CLI Reference**: `https://cli.github.com/manual/`
- **GitLab Documentation**: `https://docs.gitlab.com/`
- **Git SCM Official Documentation**: `https://git-scm.com/doc`
- **Trust Tier**: Tier 1 (Official Vendor / Project Documentation)

### Languages & Package Ecosystems
- **Python Documentation (CPython)**: `https://docs.python.org/3/`
- **Python Packaging Authority (PyPA)**: `https://packaging.python.org/`
- **Go Programming Language (Go.dev)**: `https://go.dev/doc/`
- **Rust Programming Language (Rust-lang.org)**: `https://doc.rust-lang.org/`
- **Node.js Documentation**: `https://nodejs.org/docs/`
- **TypeScript Documentation**: `https://www.typescriptlang.org/docs/`
- **Trust Tier**: Tier 1 (Official Language / Ecosystem Documentation)

### Containerization & Build Tooling
- **Docker Documentation**: `https://docs.docker.com/`
- **Open Container Initiative (OCI) Specifications**: `https://opencontainers.org/`
- **Trust Tier**: Tier 1 (Official Project / Standards Documentation)

### Collaboration & Documentation Platforms
- **Atlassian Developer Documentation (Confluence & Forge)**: `https://developer.atlassian.com/`
- **Atlassian Support & Administration**: `https://support.atlassian.com/`
- **Trust Tier**: Tier 1 (Official Vendor Documentation)

## Operational Usage

When researching software dependencies, syntax features, or workflow triggers:
1. Verify feature availability against the official language or platform version documentation.
2. Cross-check CLI syntax with official manual pages (`git-scm.com`, `cli.github.com`).
3. Ensure that CI/CD action references point to official vendor actions or verified publisher repositories.
